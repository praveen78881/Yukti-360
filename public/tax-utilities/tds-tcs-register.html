How this works

You type here Calculated — read only Compliant Needs attention

Fill the master above, then open TDS Register or TCS Register and start typing in the first row. Per row you enter about fifteen things — dates, party, PAN, section, amounts, challan. Everything else computes: rate, taxable base, tax deductible, short/excess, due date, delay, interest, quarter, form, status.

The strip at the top is live. It counts your rows, totals the tax, and adds up interest and short-deduction exposure as you type — so a late challan or a wrong rate shows up immediately, not at filing.

Nothing leaves this page. There's no server and no autosave — use Save file to write a .json you can reopen later with Open file.

Getting to the .fvu file

This page can't make a .fvu — nothing can, except NSDL's own utility. The .fvu is what the File Validation Utility outputs. It checks every challan against OLTAS live and applies several hundred version-specific rules, so a hand-built file is rejected at upload. What this page does is get you to the paste-ready stage, which is where the actual work is.

#Step
1Download RPU v1.1 and FVU v1.1 from tinpan.proteantech.in → Downloads → e-TDS/e-TCS → Quarterly Returns → Regular. Java required.
2Open RPU, pick the form, type Regular, key in the deductor details from Setup.
3Enter challans in RPU's challan sheet. Note each challan's RPU serial and put it in the register's Challan Serial column.
4Filter to one quarter above, hit Copy for RPU, paste into RPU's Annexure I grid.
5RPU → Save → Create File. Then run the FVU — this is what generates the .fvu and Form 27A.
6Zip the .fvu, upload at incometax.gov.in → e-File → Income Tax Forms → File TDS Return.

Forms were renumbered for TY 2026-27. 24Q→138, 26Q→140, 27Q→144, 27EQ→143. This year runs a separate utility track — RPU v1.1 / FVU v1.1, not the 6.0 / 9.5 versions used up to FY 2025-26. Wrong version, rejected file.
